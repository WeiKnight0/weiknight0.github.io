计算机系统由硬件和软件组成。

# 1. 信息由位和上下文构成

源文件实际上是字节序列。字符编码把字符映射为数值，再由位表示；对计算机来说，磁盘文件、内存数据和网络传输内容都只是位模式。位本身不携带唯一含义，解释规则和使用场景决定它代表什么：同一组位可以被当作整数、字符、浮点数或指令。

只由文本字符编码构成的文件通常称为文本文件，其他文件通常称为二进制文件。两者在存储层面都由字节组成，区别在于约定的解释方式。

# 2. 从源程序到可执行文件

编译系统把源代码逐步变为处理器能够执行的指令。以 `hello.c` 为例：

| 阶段 | 工具 | 主要结果 |
| --- | --- | --- |
| 预处理 | 预处理器 | 展开头文件和宏，处理条件编译，生成 `.i` 文件 |
| 编译 | 编译器 | 将预处理后的 C 程序翻译为汇编程序 `.s` |
| 汇编 | 汇编器 | 将汇编指令编码为可重定位目标文件 `.o` |
| 链接 | 链接器 | 合并目标文件和库，解析符号引用，生成可执行文件 |

# 3. 处理器如何执行程序

处理器执行的是存放在内存中的机器指令。程序运行前，操作系统将可执行文件和所需数据装入内存；处理器从程序计数器（PC）指向的位置取指，解码并执行，再更新 PC。

计算机系统的几个基本部件如下：

- **总线**在部件间传送数据。处理器通常按固定大小的数据块传输，这个块称为字；字长是体系结构的重要参数。
- **主存**保存当前正在执行的程序及其数据，通常由 DRAM 构成。
- **处理器**包含控制指令执行的逻辑、寄存器和算术逻辑单元（ALU）。寄存器保存少量高速数据，ALU 执行算术和逻辑运算。
- **I/O 设备**负责与系统外部交换数据，例如键盘、显示器和磁盘。

对 `hello` 程序而言，处理器执行的指令会从内存取出字符串等数据，并通过 I/O 机制把输出送到显示设备。程序的“运行”因此是软件指令、硬件部件和操作系统服务协作的结果。

# 4. 存储层次与局部性

处理器与主存的速度差距使得每次访问主存都可能成为执行瓶颈。系统在处理器和较慢存储设备之间加入更小、更快的缓存，暂存近期或可能再次使用的数据。

典型层次从快到慢、从小到大依次为：寄存器、处理器缓存、主存、磁盘或固态存储，以及远端存储。上层访问快但容量小、成本高；下层容量大但访问慢。缓存有效的基础是**局部性**：程序往往会重复使用刚访问过的数据：**时间局部性**，也会访问地址相近的数据**空间局部性**。

写代码时，连续访问数组通常更容易利用空间局部性；重复使用已计算的数据则能利用时间局部性。数据结构和访问模式会影响缓存命中率，进而影响程序性能。

# 5. 操作系统提供的抽象

操作系统位于应用程序与硬件之间，负责资源管理和隔离。它通过几种关键抽象简化程序的运行环境：

- **进程**让每个程序仿佛独占处理器和内存。多个进程轮流运行时，操作系统保存当前进程状态并恢复另一个进程状态，这个过程称为上下文切换。
- **虚拟内存**让每个进程看到独立、连续的地址空间。操作系统和硬件共同把虚拟地址映射到物理内存，并提供隔离与保护。
- **文件**把 I/O 设备统一抽象为字节序列及其读写操作，使程序可以用相似接口访问磁盘、终端或通信设备。

这些抽象隐藏了硬件细节，同时明确了程序可依赖的边界。理解边界有助于解释进程隔离、地址转换、系统调用和 I/O 行为。

# 6. 网络让系统彼此通信

网络把一台机器上的 I/O 扩展到其他机器。程序可以通过网络发送请求并接收响应，远端机器对本地程序来说表现为一种可访问的资源。网络通信仍然建立在数据表示、操作系统 I/O 和协议约定之上；双方必须按一致的格式解释交换的字节。

# 7. 并发、并行与抽象

**并发**描述多个任务在一段时间内交替推进的组织方式；**并行**描述多个任务在同一时刻实际执行。单处理器也可以通过上下文切换实现并发，多核处理器则能让多个执行流真正并行。

并行性可以出现在不同层次：处理器的一条指令内部可同时完成多个操作；处理器可同时执行多个指令；多核系统可同时执行多个线程或进程。并行能提升吞吐量，但程序需要正确处理共享状态和任务依赖。

## Amdahl 定律

整体加速比受未优化部分限制。若程序中比例为 $p$ 的部分加速 $s$ 倍，其余部分不变，则：

$$
S=\frac{1}{(1-p)+\frac{p}{s}}
$$

例如，若 60% 的执行时间加速 4 倍，整体加速比为 $1/(0.4+0.6/4)\approx1.82$。即使把这部分无限加速，整体加速比也不会超过 $1/(1-p)$。优化前应先找出耗时占比高的部分，并评估它对整体的上限贡献。
