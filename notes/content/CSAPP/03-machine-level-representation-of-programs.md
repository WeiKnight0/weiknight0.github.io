编译器依据 C 语言规则、操作系统约定和目标指令集生成机器代码。汇编是机器代码的文本表示：它与特定架构密切相关，但能显示高级语言如何落到寄存器、内存和控制流上。阅读汇编有助于理解优化结果、定位性能瓶颈、调试底层错误和分析安全问题。

本章例子采用 x86-64 和 AT&T 汇编语法。AT&T 语法以 `%` 标记寄存器、以 `$` 标记立即数，通常将源操作数写在目的操作数之前。Intel 语法的书写顺序相反，阅读时要先确认语法。

# 1. 机器级代码与程序编码

## 1.1 机器级抽象

指令集架构（ISA）定义处理器状态、指令格式及指令对状态的影响。机器级代码主要能看到：

- 程序计数器（PC），指向将要执行的指令。
- 整数寄存器和向量寄存器，保存数据及程序状态。
- 条件码，记录最近运算的属性。
- 虚拟地址空间，可视为按字节编址的内存数组。

机器代码不保留 C 的变量类型、数组边界或指针类型；数组和结构体都只是连续字节。某些字节被解释为整数、地址、浮点数还是指令，由执行的指令决定。

## 1.2 目标文件、可执行文件与反汇编

汇编器把汇编文本编码为机器指令和重定位信息。可重定位目标文件中的地址可能还没有最终确定；链接器合并目标文件和库，并解析符号引用，生成可执行文件。可执行文件还包含程序启动、结束及与操作系统交互所需的支持代码。

反汇编器可把机器码字节显示为汇编指令。x86-64 指令长度可变；一条指令常由少量字节构成，但操作数、前缀和寻址方式会影响长度。以 `.` 开头的汇编行通常是供汇编器或链接器使用的伪指令，不是处理器执行的操作。

# 2. 数据格式、寄存器和访存

## 2.1 整数数据格式

常见指令后缀表示数据宽度：

| 后缀 | 位宽 | 常见名称 |
| --- | ---: | --- |
| `b` | 8 | byte |
| `w` | 16 | word |
| `l` | 32 | double word |
| `q` | 64 | quad word |

浮点数据使用不同格式和指令。汇编指令本身通常不记录 C 的 `long`、`long long` 等类型名；要结合调用约定、数据宽度和上下文推断。

## 2.2 通用寄存器

x86-64 有 16 个通用 64 位寄存器。常见角色和调用约定如下（System V AMD64 ABI）：

| 寄存器 | 常见用途 |
| --- | --- |
| `%rax` | 整数返回值、算术结果 |
| `%rsp` | 栈指针 |
| `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9` | 前六个整数或指针参数 |
| `%rbx`, `%rbp`, `%r12`–`%r15` | 被调用者保存寄存器 |
| `%r10`, `%r11` | 调用者保存的临时寄存器 |

寄存器的低位部分可单独命名，例如 `%rax`、`%eax`、`%ax`、`%al` 分别表示 64、32、16、8 位低位。写入 8 位或 16 位子寄存器只修改相应位；写入 32 位寄存器会把 64 位寄存器的高 32 位清零。

## 2.3 操作数与寻址

指令操作数可以是立即数、寄存器或内存引用。常见内存寻址写作：

```text
D(base, index, scale)
```

有效地址为 $D+R[base]+R[index]\times scale$，其中 `scale` 只能是 1、2、4 或 8。例如 `9(%rdi,%rsi,4)` 的地址为 `%rdi + %rsi × 4 + 9`。

要区分计算地址和访问内存：

```asm
leaq 9(%rdi,%rsi,4), %rax  # rax = rdi + rsi*4 + 9
movq 9(%rdi,%rsi,4), %rax  # 从该地址读取 8 字节到 rax
```

`leaq` 不读取内存，虽然名字中有 `lea`；编译器也常用它计算加法和有限形式的乘法。

## 2.4 数据传送指令

`mov` 在寄存器、内存和立即数间传送位模式。源和目的不能同时是内存；若要在两个内存位置间复制，必须先经寄存器中转。寄存器和指令后缀的宽度必须匹配。

- `movb`、`movw`、`movl` 分别传送 1、2、4 字节。
- `movq` 传送 8 字节；作为源的立即数编码通常只有 32 位并符号扩展到 64 位。
- `movabsq` 可把任意 64 位立即数传送到寄存器。
- `movz` 系列把窄值零扩展到宽寄存器；`movs` 系列做符号扩展。
- `cltq` 将 `%eax` 的 32 位补码符号扩展到 `%rax`，等价于 `movslq %eax, %rax`。

例如，`movzbl (%rdi), %eax` 从 `%rdi` 指向的位置读 1 字节并零扩展到 32 位；`movsbl (%rdi), %eax` 则复制该字节的符号位。

## 2.5 压栈与出栈

运行时栈通常向低地址增长，`%rsp` 保存栈顶地址。`pushq %rax` 将 `%rsp` 减 8，再把 `%rax` 写入新的栈顶；`popq %rax` 先从栈顶读取 8 字节，再将 `%rsp` 加 8。栈帧中的其他位置可用常规内存寻址访问，并不局限于栈顶。

# 3. 算术与逻辑操作

常见操作包括：

| 类别 | 指令示例 | 效果（AT&T：源, 目的） |
| --- | --- | --- |
| 加载有效地址 | `leaq S, D` | 把有效地址计算结果写入寄存器 `D` |
| 一元运算 | `inc D`, `dec D`, `neg D`, `not D` | 自增、自减、取负、按位取反 |
| 二元运算 | `add S,D`, `sub S,D`, `imul S,D` | `D=D+S`、`D=D-S`、低位乘积 |
| 位逻辑 | `and`, `or`, `xor` | 按位与、或、异或 |
| 移位 | `sal`, `shl`, `sar`, `shr` | 左移、算术右移、逻辑右移 |

二元指令的第二个操作数同时是源和目的。`sub S,D` 计算 `D-S`，容易因操作数顺序看反。若目的操作数是内存，处理器可读取、运算并写回；但仍不允许两个内存操作数。

移位量可以是立即数，也可以放在 `%cl` 中。x86-64 对移位量按操作数宽度取低位：64 位操作取低 6 位，32 位操作取低 5 位。`sal` 与 `shl` 同义；`sar` 高位补符号位，`shr` 高位补 0。

两个 64 位整数相乘可能需要 128 位结果。`mul`/`imul` 和 `div`/`idiv` 提供不同宽度及有符号/无符号形式；常见 64 位全宽乘除使用 `%rdx:%rax` 作为 128 位被除数或乘积的一部分。分析时要同时追踪高低半部寄存器及符号扩展。

# 4. 条件码与控制流

## 4.1 条件码

条件码是独立于通用寄存器的状态位，描述最近算术或逻辑运算的结果：

- **CF**：无符号进位或借位信息。
- **ZF**：结果为零。
- **SF**：结果的符号位为 1。
- **OF**：补码有符号溢出。

多数算术和逻辑指令会更新条件码；`leaq` 不更新。`cmp S,D` 类似计算 `D-S` 并设置条件码，但不保存结果；`test S,D` 类似计算 `S & D` 并设置条件码，也不保存结果。

## 4.2 `set` 与条件跳转

条件码可用于设置一个字节、条件跳转或条件传送。`setcc` 把条件结果写成 0 或 1，例如 `sete` 在相等时写 1，`setl` 在有符号小于时写 1。目的只能是 8 位寄存器或 1 字节内存位置。

有符号和无符号比较使用不同条件：

| 关系 | 有符号跳转 | 无符号跳转 |
| --- | --- | --- |
| 小于 | `jl` | `jb` |
| 小于等于 | `jle` | `jbe` |
| 大于 | `jg` | `ja` |
| 大于等于 | `jge` | `jae` |
| 等于 / 不等于 | `je` / `jne` | `je` / `jne` |

数据本身不会标注有符号或无符号；编译器通过选择不同的比较、移位、乘除和条件跳转指令表达 C 类型语义。

## 4.3 跳转与分支

`jmp` 是无条件跳转，其他 `jcc` 指令按条件码决定是否跳转。目标可以是直接标签；`jmp *%rax` 或 `jmp *(%rax)` 是间接跳转，目标地址来自寄存器或内存。x86-64 的条件跳转目标通常编码为相对位移，汇编器和链接器选择合适的编码长度。

编译器可以用条件跳转实现 `if`，也可能用 `cmovcc` 有条件地传送数据。条件传送可减少分支预测失败的代价，但会无条件计算候选值；若候选计算可能访问非法地址或产生副作用，就不能随意替换分支。

`while`、`for`、`do-while` 最终都是标签、条件跳转和回边的组合。`switch` 可编译为比较链，也可编译为跳转表；分支值密集时跳转表较合适，稀疏或数量少时比较链可能更合适。

例如，C 表达式 `if (x < y) i++; else i--;` 对应的思路是比较 `x` 与 `y`，条件跳转到一个分支，再执行另一条路径。具体寄存器分配和分支布局由编译器决定。

# 5. 过程调用与运行时栈

过程（函数）调用需要传递参数、保存返回地址、分配局部空间并返回结果。System V AMD64 ABI 的常见约定是：

- 前六个整数或指针参数依次放在 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`；其余参数通过栈传递。
- 整数或指针返回值放在 `%rax`。
- `%rbx`、`%rbp`、`%r12`–`%r15` 是被调用者保存寄存器；若被调用函数使用，必须恢复原值。
- `%rax`、参数寄存器及 `%r10`、`%r11` 通常由调用者保存；调用方若需跨调用保留值，应自行保存。
- 常见 System V AMD64 调用点要求栈按 16 字节对齐。

`call` 把返回地址压栈并跳转到被调用过程；`ret` 从栈顶取回返回地址。过程可通过减少 `%rsp` 分配栈帧，用栈保存局部变量、溢出的参数或寄存器值。优化构建中，局部变量可能留在寄存器中，帧指针也可能被省略。

递归调用会为每次活动调用保留独立的返回地址和必要状态。理解递归汇编时，关键是追踪每层调用的栈指针、参数和返回值。

# 6. 数组与数据结构布局

## 6.1 数组和指针运算

若元素宽度为 $L$ 字节、数组基址为 $x_a$，则第 $i$ 个元素地址为：

$$
\&x[i]=x_a+iL
$$

C 中 `a[i]` 等价于 `*(a+i)`。指针加法按所指类型大小缩放，所以 `T *p; p+i` 前进 `i × sizeof(T)` 字节。

二维数组按行优先存储。列数为 $C$、元素宽度为 $L$ 时，`A[i][j]` 地址为：

$$
x_A+(iC+j)L
$$

变长数组的维度在运行时确定，编译器会用运行时计算生成偏移；这类对象可能需要动态调整栈帧。

## 6.2 结构、联合与对齐

结构体字段按声明顺序排列，但编译器可能插入填充以满足字段对齐。结构体大小通常会向最大成员对齐要求取整；因此 `sizeof` 可能大于成员大小之和。

联合体成员共享同一段存储，大小至少足以容纳最大成员。联合体适合复用存储空间，但程序必须自行记录当前有效成员，不能把任意位模式当成有效成员值。

## 6.3 指针与调试

调试机器级程序时，应区分指针保存的地址、地址处的值和对象的类型解释。GDB 可检查寄存器、内存、反汇编和栈帧；当优化导致变量消失或被放入寄存器时，调试信息可能无法对应到简单的源码变量布局。

# 7. 内存越界与缓冲区溢出

机器码不自动检查数组下标或缓冲区长度。写入超出对象边界可能覆盖相邻数据，严重时会修改保存的控制信息或返回地址，导致崩溃或控制流被劫持。

常见防护包括栈保护 canary、地址空间布局随机化（ASLR）、不可执行内存（NX）和位置无关代码（PIC）。这些机制提高利用难度，不能取代长度检查和安全的内存操作。变长局部对象还会使栈帧大小在运行时计算，分析时不能假定所有局部数据具有固定偏移。

# 8. 浮点机器代码

x86-64 通常用 XMM 寄存器和 SSE 指令执行浮点操作。浮点参数和返回值遵循 ABI 的浮点规则，与整数参数寄存器规则不同。指令后缀常以 `ss` 表示标量单精度、`sd` 表示标量双精度；转换指令负责在整数与浮点寄存器间转换。

浮点比较也会设置条件状态。NaN 与任何值（包括自身）都不相等，条件分支必须考虑无序比较情形。启用快速数学选项时，编译器可能采用不保留全部 IEEE 754 特性的优化假设。

# 9. 阅读汇编的检查顺序

1. 确认架构、汇编语法、ABI 和优化选项。
2. 找出函数边界、标签、条件跳转和回边，先还原控制流。
3. 跟踪参数寄存器、栈槽和返回值寄存器。
4. 逐条确认操作数宽度、寻址表达式和内存读写。
5. 检查符号扩展/零扩展，以及比较采用有符号还是无符号语义。
6. 对照 C 类型规则检查溢出、越界和浮点特殊值。

# 本章要点

- ISA 描述机器代码可见的状态和指令行为；汇编是机器码的可读表示。
- AT&T 语法中源操作数在前、目的操作数在后；`sub S,D` 执行 `D-S`。
- `leaq` 只计算地址；`mov` 才会访问相应内存。
- 条件码连接算术结果与分支；有符号与无符号比较必须选对条件。
- ABI 规定参数、返回值、寄存器保存和栈对齐，是函数互操作的约定。
- 数组地址由基址、元素大小和索引决定；结构体布局还受对齐和填充影响。
- 越界访问可能破坏数据或控制流；硬件执行机器代码时不会自动恢复 C 的边界信息。
