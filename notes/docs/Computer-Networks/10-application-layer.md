# 网络应用基础

网络应用是运行在不同端系统并通过网络相互通信的程序。网络核心设备负责转发数据，不运行这些应用。

应用层协议规定不同端系统上的应用程序如何通信，包括消息格式、消息类型和字段含义，以及发送消息的时间和顺序。开放协议由 RFC 定义，专用协议由应用开发者自行定义。

## 网络应用的进程通信方式

网络应用的进程通信方式有 Client/Server 模式（C/S）、Browser/Server 模式（B/S）、Peer to Peer 模式（P2P）。

- Client/Server 模式（C/S）：服务器总是运行、提供服务，有固定 IP 地址，数据中心常用于创建强大虚拟服务器；客户端主动和服务器通信、请求服务，可间断连接，可有动态 IP 地址，客户端之间不直接通信。
- Peer to Peer 模式（P2P）：任意端系统之间可直接通信，每一个端系统既可以请求服务，也可以提供服务（自扩展性），端系统之间间断连接，本质上仍使用 C/S 模式，但强调进程对等，每个 P2P 进程既是客户端又是服务器。
- Browser/Server 模式（B/S）：浏览器作为通用客户端，通过 Web 协议访问服务器提供的应用。

## Socket 与传输服务

Socket 是同一主机中应用层与传输层之间的接口。应用程序需要显式创建、使用和释放 Socket。

两种传输服务分别是不可靠的数据报服务和可靠的字节流服务。

- 不可靠的数据报服务：由 UDP 协议实现，使用 <IP 地址，端口号> 二元组进行标识；服务器的传输层收到 UDP 报文后检查目的端口号，将报文交付到对应端口号的套接字；< 目的 IP 地址，目的端口号 > 相同的 UDP 报文段被交付给同一个套接字，与 < 源 IP 地址，源端口号 > 无关；服务器使用一个套接字服务所有客户，报文段中的 < 源 IP 地址，源端口号 > 被接收进程用来发送响应报文。
- 可靠的字节流服务：由 TCP 协议实现，使用 <源 IP 地址，目的 IP 地址，源端口号，目的端口号> 四元组进行标识；服务器使用该四元组将 TCP 报文交付到正确的连接套接字，服务器为每个客户端创建一个套接字。

## 服务器进程

服务器进程的工作方式有无连接的循环方式（iterative mode）和面向连接的并发方式（concurrent mode）。

- 无连接的循环方式：一次只运行一个服务进程；当有多个客户进程请求服务时，服务进程按请求先后顺序依次响应（阻塞方式）；适用于无连接的 UDP 服务，按序服务；服务进程只使用一个服务套接字，每个客户使用自己设定端口号的客户套接字。
- 面向连接的并发方式：可以同时运行多个服务进程；每个服务进程对某个特定的客户进程做出响应（非阻塞方式）；主服务进程（知名端口）收到客户端请求后创建从服务进程（临时 socket）；主服务进程也称为父服务进程，从属服务进程称为子服务进程，主服务进程一般使用服务器的知名端口号；适用于面向连接的 TCP 服务。

# DNS

DNS 既是由多级域名服务器组成的分布式数据库，也是供其他网络应用使用的应用层协议。主机和域名服务器通常通过 UDP 端口 53 通信，完成域名到 IP 地址的解析。

DNS 服务器分为根域名服务器、顶级域名服务器、权威域名服务器和本地域名服务器。本地域名服务器由 ISP 提供，接收主机的查询并代理后续查询；根服务器指引查询到顶级域名服务器，顶级域名服务器再指引查询到相应的权威服务器。

## DNS 的服务

DNS 提供的服务包括：

- 主机名到 IP 地址的转换；
- 主机别名到规范主机名的转换（可多个主机别名指向同一个规范主机名）；
- 邮件服务器别名到邮件服务器规范主机名的转换；
- 实现负载分配：一个 IP 地址集合与同一个规范主机名联系。

## 分布式、层次化 DNS

不采用集中式 DNS 的原因：

- 单点故障：一旦集中式服务器出现问题，整个 DNS 系统瘫痪；
- 性能瓶颈：所有 DNS 查询都集中到一台服务器，处理压力大，查询响应延迟大；
- 系统维护困难，可扩展性差：随着互联网主机数量增加，集中式服务器难以承载。

分布式、层次化 DNS 的优势：由大量 DNS 服务器层次化组织，分布在全世界范围，避免单点故障和性能瓶颈，维护更便捷，可扩展性强。

## 域名结构

DNS 的域名结构特点：采用层次树状结构的命名方法，由若干个分量组成，各分量之间用小数点 “.” 隔开（至少一个），总长不超过 255 个字符；各分量不区分大小写，分别代表不同级别的域名（≤63 字符），从左到右域名级别依次增加；各级域名由上一级域名管理机构管理，最高的顶级域名由 ICANN 管理。

## DNS 查询

DNS 域名解析的两种查询方式为迭代查询（常用方式）和递归查询。

- 迭代查询流程（以请求主机查询 www.baidu.com 为例）：
  1. 请求主机（cse.seu.edu.cn）向本地域名服务器（dns.seu.edu.cn）发送查询请求；
  2. 本地域名服务器向根域名服务器发送查询请求；
  3. 根域名服务器返回顶级域名服务器（.com DNS servers）的 IP 地址给本地域名服务器；
  4. 本地域名服务器向顶级域名服务器发送查询请求；
  5. 顶级域名服务器返回权威域名服务器（dns.baidu.com）的 IP 地址给本地域名服务器；
  6. 本地域名服务器向权威域名服务器发送查询请求；
  7. 权威域名服务器返回 www.baidu.com 对应的 IP 地址给本地域名服务器；
  8. 本地域名服务器将 IP 地址返回给请求主机。

- 递归查询流程（以请求主机查询 www.baidu.com 为例）：
  1. 请求主机（cse.seu.edu.cn）向本地域名服务器（dns.seu.edu.cn）发送查询请求，请求本地服务器递归查询；
  2. 本地域名服务器向根域名服务器发送递归查询请求；
  3. 根域名服务器向顶级域名服务器发送查询请求；
  4. 顶级域名服务器向权威域名服务器发送查询请求；
  5. 权威域名服务器返回 www.baidu.com 对应的 IP 地址给顶级域名服务器；
  6. 顶级域名服务器将 IP 地址返回给根域名服务器；
  7. 根域名服务器将 IP 地址返回给本地域名服务器；
  8. 本地域名服务器将 IP 地址返回给请求主机。

## DNS 资源记录

DNS 记录格式：（name, value, type, TTL），其中 TTL 是该记录的生存时间。

常见记录类型及含义：

- type=A：Name 是主机名，Value 是 IP 地址；
- type=NS：Name 是域名（如 edu.cn），Value 是权威 DNS 服务器主机名；
- type=CNAME：Name 是主机别名，Value 是规范主机名；
- type=MX：Name 是邮件服务器别名，Value 是邮件服务器规范主机名。

## nslookup

nslookup 是 DNS 查询命令，用于查询域名对应的 IP 地址等 DNS 相关信息。执行该命令时，会显示执行查询的域名服务器及 IP 地址，若返回非权威应答，则表示结果未经验证，不是直接由权威域名服务器提供；查询结果中会包含域名对应的规范主机名、IP 地址（可能包含 IPv4 和 IPv6 地址）以及主机别名等信息。例如执行 “nslookup [www.seu.edu.cn](https://www.seu.edu.cn)” 可查询该域名对应的 IP 地址等详细信息。

# Web 与 HTTP

Web 页面由 HTML 文档以及图像、视频、声音和脚本等对象组成。URL 用于定位 Web 对象，基本格式为“协议类型://主机名:端口/路径和文件名”。RTT 是一个分组从客户端到服务器再返回客户端所用的时间。

## HTTP 与 SMTP

HTTP 协议的特点：

- Web 应用的应用层协议，基于 TCP（端口 80）；
- 无状态协议：服务器不保存关于客户的任何信息；
- 支持非持续连接（HTTP1.0）和持续连接（HTTP1.1 及以上）；
- 客户端初始化 TCP 连接，发送请求，接收并显示 Web 对象；服务器接收 TCP 连接请求，发送 Web 对象作为响应，数据传输完关闭 TCP 连接。

HTTP 与 SMTP 的区别：

- 信息获取方式：HTTP 是拉协议（客户端主动获取服务器资源），SMTP 是推协议（发送方主动将邮件推送给接收方）；
- 报文编码格式：HTTP 没有要求，SMTP 采用 7 比特 ASCII 码格式；
- 信息封装方式：HTTP 每个对象分别封装到自己的响应报文中（每个对象单独请求），SMTP 所有对象放在一个报文中。

## 非持续与持续 HTTP 连接

区别：非持续连接中每个 TCP 连接只传输一个请求报文和一个响应报文，下载多个对象需要多次 TCP 连接；持续连接中所有客户端和服务器的请求 / 响应对都经相同的 TCP 连接发送，下载多个对象仅需要一次 TCP 连接。

非持续连接（HTTP1.0）优缺点：

- 优点：实现简单；
- 缺点：时间开销大（请求每个对象需要 2 个 RTT）；资源开销大（浏览器通常打开多个 TCP 连接）。

持续连接（HTTP1.1）优缺点：

- 优点：降低时间开销（无需多次建立 TCP 连接）和资源开销（减少 TCP 连接数量）；
- 缺点：实现相对复杂，服务器需维护连接状态。

## HTTP 报文

HTTP 请求报文结构：

- 请求行：方法（Get/Post/Head/Put/Delete 等）+ 空格 + URL + 空格 + HTTP 版本 + 回车换行符；
- 首部行：首部字段名 + 冒号 + 空格 + 值 + 回车换行符（可多个）；
- 报文体：Post 方法使用，用于提交表单（首部行结束后加回车换行符标识报文体开始）。

HTTP 响应报文结构：

- 状态行：HTTP 版本 + 空格 + 状态码 + 空格 + 状态信息 + 回车换行符；
- 首部行：首部字段名 + 冒号 + 空格 + 值 + 回车换行符（可多个）；
- 报文体（实体体）：请求的对象数据（首部行结束后加回车换行符标识报文体开始）。

## Cookie

Cookie 技术的构成：

- HTTP 响应报文中的 cookie 首部行；
- HTTP 请求报文中的 cookie 首部行；
- 客户端保留的 cookie 文件（由浏览器进行管理）；
- 服务器端在后端数据库产生的相应表项。

Cookie 的作用：维护用户和服务器的状态，支持认证、购物、个性化推荐等功能。

Cookie 的优点：

- 能分析用户喜好，向用户进行个性化推荐；
- 可标识用户信息，记录用户购物清单；
- 可保存 4K 内容，跟踪用户浏览网站的喜好；
- 可跨站点跟踪用户点击广告。

Cookie 的缺点：

- 能跟踪用户网络浏览痕迹，泄露用户隐私（如浏览过的网站、关注的关键词等）；
- 存在被误解为嵌入间谍程序的误区（实际 Cookie 文件仅保存文本串，无执行程序）。

## Web 缓存与条件 GET

Web 缓存的作用：

- 大大减少响应时间：若请求对象在缓存中，可直接返回，无需访问源服务器；
- 大大减少接入网到 Internet 的通信量，降低资费；
- 大大减少 Internet 上的 Web 流量，改善网络性能。

条件 Get 方法的原理：目的是确保 Web 缓存中保存的对象是最新版本；缓存服务器发出的 Get 请求报文中含有 “If Modified-Since:\<date\>” 的首部行；若对象在该日期之后没有被修改，源服务器返回 304 Not Modified 响应（无报文体），缓存服务器直接使用缓存中的对象；若对象在该日期之后被修改，源服务器返回 200 OK 响应，附带修改后的对象数据，缓存服务器更新缓存并返回给客户端。

# 电子邮件

## 电子邮件系统

E-mail 系统由用户代理、邮件服务器、SMTP 协议、邮件访问协议（POP3/IMAP/HTTP）组成。

- 用户代理：即邮件客户端软件，供用户编写、发送、接收和阅读邮件；
- 邮件服务器：包含输出报文队列（存储发送方待发送的邮件）和邮箱（存储接收方收到的邮件），是邮件传输的中转节点；
- SMTP 协议：使用 TCP 端口 25 发送电子邮件，客户端为用户代理或发送邮件服务器，服务器为接收邮件服务器，实现发送邮件服务器到接收邮件服务器的直接传输；
- 邮件访问协议（POP3/IMAP）：供邮件客户端从服务器获取邮件信息，其中 POP3 支持认证、下载、标记删除和更新功能，IMAP 支持远程管理邮件（创建文件夹、移动邮件等）

## 邮件访问协议

- POP3（Post Office Protocol v3）：

  - 端口：使用 TCP，端口 110；

  - 工作阶段：分为认证、事务处理（下载、标记删除）、更新（删除）三个阶段；

  - 邮件存储：邮件下载到客户端后，服务器端可默认删除，主要依赖客户端本地管理邮件；

  - 核心特点：功能简洁，仅支持基本的邮件下载和删除操作，适用于对邮件管理需求简单的场景。

- IMAP（Internet Mail Access Protocol）：
  - 端口：使用 TCP，端口 143；
  - 邮件存储：邮件始终保留在服务器端，客户端通过远程操作管理邮件；
  - 核心特点：支持远程创建文件夹、远程移动邮件、远程查询邮件、获取邮件部分信息等功能，灵活性和功能性更强，适用于需要多设备同步邮件、精细化管理邮件的场景。
- HTTP（基于 Web 的邮件访问协议）：
  - 核心特点：用户代理为浏览器，提供位于 POP3/IMAP 之上的、基于 Web 的邮件信息获取访问接口；无需安装专门的邮件客户端，通过浏览器即可访问邮件服务器，操作便捷，适用于临时访问或对客户端安装有限制的场景。
