# Application Layer 应用层

## 一、核心概念定义

1. **网络应用：运行在不同端系统（分布式），且通过网络彼此通信的程序（进程）**，例如 Web 应用（Web 服务器、浏览器），网络核心设备上不运行网络应用。
2. 应用层协议：**规定了运行在不同端系统上的应用程序如何相互通信**，包括语法（消息格式）、语义（消息类型、字段含义）、时序（什么时候以及如何发送消息的规则），是网络应用的一部分，分为开放协议（RFC 定义）和专用协议（非 RFC 定义）。
3. Client/Server 模式（C/S）：服务器总是运行、提供服务，有固定 IP 地址，数据中心常用于创建强大虚拟服务器；客户端主动和服务器通信、请求服务，可间断连接，可有动态 IP 地址，客户端之间不直接通信。
4. Peer to Peer 模式（P2P）：任意端系统之间可直接通信，每一个端系统既可以请求服务，也可以提供服务（自扩展性），端系统之间间断连接，本质上仍使用 C/S 模式，但强调进程对等，每个 P2P 进程既是客户端又是服务器。
5. Socket（套接字）：同一台主机内应用层与传输层之间的接口，应用需显式地创建、使用和释放套接字，采用客户端 - 服务器模式，通过 socket API 调用不可靠的数据报服务和可靠的字节流服务。
6. DNS（域名系统）：既是网络应用又是应用层协议，分布式数据库系统（由许多域名服务器分层实现），应用层协议方面，主机和域名服务器通过 UDP（端口 53）通信实现域名到 IP 地址的解析，不直接和用户打交道，由其他应用层协议使用。
7. 规范主机名：具有唯一性的主机名，例如[relay1.west-coast.enterprise.com](https://relay1.west-coast.enterprise.com)。
8. 主机别名：更易记忆的主机名，可多个指向同一个规范主机名，例如[www.enterprise.com](https://www.enterprise.com)。
9. 根域名服务器：IPv4 全球 13 个（10 个在美国、2 个在欧洲、1 个在日本），提供顶级域名服务器的 IP 地址；中国有 3 个根域名镜像服务器，主导构建 25 台 IPv6 根服务器（中国 4 台）。
10. 顶级域名服务器：提供顶级域名下权威域名服务器的 IP 地址。
11. 权威域名服务器：每个组织机构自己的 DNS 服务器，按照域名级别可以有多个。
12. 本地域名服务器（LDNS）：每个 ISP 都有一个，当主机发出 DNS 请求时，该请求被发往本地域名服务器，起着代理的作用。
13. Web 页面（HTML 文档）：包含多种对象或链接，Web 对象包括静态对象和动态对象（HTML 文档、图像文件、视频文件、声音文件、脚本文件等）。
14. URL（统一资源定位符）：用于对 Web 对象编址，格式为协议类型:// 主机名：端口 / 路径和文件名。
15. HTTP（HyperText Transfer Protocol）：Web 应用的应用层协议，基于 TCP（端口 80），客户端通过其发送请求、初始化 TCP 连接、接收并显示 Web 对象，服务器接收 TCP 连接请求并通过其发送 Web 对象，数据传输完关闭 TCP 连接。
16. 非持续连接：每个 TCP 连接只传输一个请求报文和一个响应报文，下载多个对象需要多次 TCP 连接（HTTP1.0 默认）。
17. 持续连接：所有客户端和服务器的请求 / 响应对都经相同的 TCP 连接发送，下载多个对象仅需要一次 TCP 连接（HTTP1.1 默认）。
18. RTT（Round-Trip Time）：一个分组从客户端到服务器的往返时间。
19. Cookie：用于维护用户和服务器状态的技术，由 HTTP 响应报文中的 cookie 首部行、HTTP 请求报文中的 cookie 首部行、客户端保留的 cookie 文件（浏览器管理）、服务器端后端数据库的相应表项构成。
20. Web 缓存：浏览器发送所有 HTTP 请求到缓存，若请求对象在缓存中则直接返回，否则缓存向源服务器请求对象后再返回给浏览器。
21. 条件 Get 方法：确保 Web 缓存中保存的对象是最新版本的方法，缓存服务器发出的 Get 请求报文中含有 “If Modified-Since:\<date\>” 的首部行。
22. E-mail 系统：由用户代理（邮件客户端软件）、邮件服务器（含输出报文队列（发送方）、邮箱（接收方））、简单邮件传输协议（SMTP）、邮件访问协议（POP3/IMAP/HTTP）组成。
23. SMTP（简单邮件传输协议）：应用层协议，使用 TCP（端口 25），用于发送电子邮件，客户端为用户代理 / 发送邮件服务器，服务器为接收邮件服务器，发送邮件服务器到接收邮件服务器直接传输，不使用中间邮件服务器转发。
24. POP3（Post Office Protocol v3）：邮件访问协议，使用 TCP（端口 110），包含认证、事务处理（下载、标记删除）、更新（删除）三个阶段。
25. IMAP（Internet Mail Access Protocol）：邮件访问协议，使用 TCP（端口 143），邮件在服务器端，支持远程创建文件夹、远程移动邮件、远程查询邮件、获取邮件部分信息。

## 二、必考简答题预测

### （一）网络应用基础

1. 问题：网络应用的进程通信方式有哪些？分别简述其特点。

   答案：网络应用的进程通信方式有 Client/Server 模式（C/S）、Browser/Server 模式（B/S）、Peer to Peer 模式（P2P）。

   - Client/Server 模式（C/S）：服务器总是运行、提供服务，有固定 IP 地址，数据中心常用于创建强大虚拟服务器；客户端主动和服务器通信、请求服务，可间断连接，可有动态 IP 地址，客户端之间不直接通信。
   - Peer to Peer 模式（P2P）：任意端系统之间可直接通信，每一个端系统既可以请求服务，也可以提供服务（自扩展性），端系统之间间断连接，本质上仍使用 C/S 模式，但强调进程对等，每个 P2P 进程既是客户端又是服务器。
   - Browser/Server 模式（B/S）：文档中未详细展开，核心是基于浏览器作为客户端与服务器进行通信。

2. 问题：Socket API 调用的两种传输服务分别是什么？各自的标识方式和特点是什么？

   答案：两种传输服务分别是不可靠的数据报服务和可靠的字节流服务。

   - 不可靠的数据报服务：由 UDP 协议实现，使用 <IP 地址，端口号> 二元组进行标识；服务器的传输层收到 UDP 报文后检查目的端口号，将报文交付到对应端口号的套接字；< 目的 IP 地址，目的端口号 > 相同的 UDP 报文段被交付给同一个套接字，与 < 源 IP 地址，源端口号 > 无关；服务器使用一个套接字服务所有客户，报文段中的 < 源 IP 地址，源端口号 > 被接收进程用来发送响应报文。
   - 可靠的字节流服务：由 TCP 协议实现，使用 <源 IP 地址，目的 IP 地址，源端口号，目的端口号> 四元组进行标识；服务器使用该四元组将 TCP 报文交付到正确的连接套接字，服务器为每个客户端创建一个套接字。

3. 问题：服务器进程的工作方式有哪些？分别简述其特点和适用场景。

   答案：服务器进程的工作方式有无连接的循环方式（iterative mode）和面向连接的并发方式（concurrent mode）。

   - 无连接的循环方式：一次只运行一个服务进程；当有多个客户进程请求服务时，服务进程按请求先后顺序依次响应（阻塞方式）；适用于无连接的 UDP 服务，按序服务；服务进程只使用一个服务套接字，每个客户使用自己设定端口号的客户套接字。
   - 面向连接的并发方式：可以同时运行多个服务进程；每个服务进程对某个特定的客户进程做出响应（非阻塞方式）；主服务进程（知名端口）收到客户端请求后创建从服务进程（临时 socket）；主服务进程也称为父服务进程，从属服务进程称为子服务进程，主服务进程一般使用服务器的知名端口号；适用于面向连接的 TCP 服务。

### （二）DNS 相关

1. 问题：DNS 提供的服务有哪些？

   答案：DNS 提供的服务包括：

   - 主机名到 IP 地址的转换；
   - 主机别名到规范主机名的转换（可多个主机别名指向同一个规范主机名）；
   - 邮件服务器别名到邮件服务器规范主机名的转换；
   - 实现负载分配：一个 IP 地址集合与同一个规范主机名联系。

2. 问题：为什么不采用集中式 DNS？分布式、层次化 DNS 的优势是什么？

   答案：不采用集中式 DNS 的原因：

   - 单点故障：一旦集中式服务器出现问题，整个 DNS 系统瘫痪；
   - 性能瓶颈：所有 DNS 查询都集中到一台服务器，处理压力大，查询响应延迟大；
   - 系统维护困难，可扩展性差：随着互联网主机数量增加，集中式服务器难以承载。

   分布式、层次化 DNS 的优势：由大量 DNS 服务器层次化组织，分布在全世界范围，避免单点故障和性能瓶颈，维护更便捷，可扩展性强。

3. 问题：DNS 的域名结构有什么特点？

   答案：DNS 的域名结构特点：采用层次树状结构的命名方法，由若干个分量组成，各分量之间用小数点 “.” 隔开（至少一个），总长不超过 255 个字符；各分量不区分大小写，分别代表不同级别的域名（≤63 字符），从左到右域名级别依次增加；各级域名由上一级域名管理机构管理，最高的顶级域名由 ICANN 管理。

4. 问题：DNS 的域名解析过程有哪两种查询方式？分别简述其流程。

   答案：DNS 域名解析的两种查询方式为迭代查询（常用方式）和递归查询。

   - 迭代查询流程（以请求主机查询 www.baidu.com 为例）：
     1. 请求主机（cse.seu.edu.cn）向本地域名服务器（dns.seu.edu.cn）发送查询请求；
     2. 本地域名服务器向根域名服务器发送查询请求；
     3. 根域名服务器返回顶级域名服务器（.com DNS servers）的 IP 地址给本地域名服务器；
     4. 本地域名服务器向顶级域名服务器发送查询请求；
     5. 顶级域名服务器返回权威域名服务器（dns.baidu.com）的 IP 地址给本地域名服务器；
     6. 本地域名服务器向权威域名服务器发送查询请求；
     7. 权威域名服务器返回 www.baidu.com 对应的 IP 地址给本地域名服务器；
     8. 本地域名服务器将 IP 地址返回给请求主机。

   - 递归查询流程（以请求主机查询 www.baidu.com 为例）：
     1. 请求主机（cse.seu.edu.cn）向本地域名服务器（dns.seu.edu.cn）发送查询请求，请求本地服务器递归查询；
     2. 本地域名服务器向根域名服务器发送递归查询请求；
     3. 根域名服务器向顶级域名服务器发送查询请求；
     4. 顶级域名服务器向权威域名服务器发送查询请求；
     5. 权威域名服务器返回 www.baidu.com 对应的 IP 地址给顶级域名服务器；
     6. 顶级域名服务器将 IP 地址返回给根域名服务器；
     7. 根域名服务器将 IP 地址返回给本地域名服务器；
     8. 本地域名服务器将 IP 地址返回给请求主机。

5. 问题：DNS 记录的格式是什么？常见的记录类型（type）有哪些？各自的 name 和 value 含义是什么？

   答案：DNS 记录格式：（name, value, type, TTL），其中 TTL 是该记录的生存时间。

   常见记录类型及含义：

   - type=A：Name 是主机名，Value 是 IP 地址；
   - type=NS：Name 是域名（如 edu.cn），Value 是权威 DNS 服务器主机名；
   - type=CNAME：Name 是主机别名，Value 是规范主机名；
   - type=MX：Name 是邮件服务器别名，Value 是邮件服务器规范主机名。

6. 问题：简述 nslookup。

   答案：nslookup 是 DNS 查询命令，用于查询域名对应的 IP 地址等 DNS 相关信息。执行该命令时，会显示执行查询的域名服务器及 IP 地址，若返回非权威应答，则表示结果未经验证，不是直接由权威域名服务器提供；查询结果中会包含域名对应的规范主机名、IP 地址（可能包含 IPv4 和 IPv6 地址）以及主机别名等信息。例如执行 “nslookup [www.seu.edu.cn](https://www.seu.edu.cn)” 可查询该域名对应的 IP 地址等详细信息。

### （三）Web 和 HTTP 相关

1. 问题：HTTP 协议的特点是什么？HTTP 与 SMTP 的区别有哪些？

   答案：HTTP 协议的特点：

   - Web 应用的应用层协议，基于 TCP（端口 80）；
   - 无状态协议：服务器不保存关于客户的任何信息；
   - 支持非持续连接（HTTP1.0）和持续连接（HTTP1.1 及以上）；
   - 客户端初始化 TCP 连接，发送请求，接收并显示 Web 对象；服务器接收 TCP 连接请求，发送 Web 对象作为响应，数据传输完关闭 TCP 连接。

   HTTP 与 SMTP 的区别：

   - 信息获取方式：HTTP 是拉协议（客户端主动获取服务器资源），SMTP 是推协议（发送方主动将邮件推送给接收方）；
   - 报文编码格式：HTTP 没有要求，SMTP 采用 7 比特 ASCII 码格式；
   - 信息封装方式：HTTP 每个对象分别封装到自己的响应报文中（每个对象单独请求），SMTP 所有对象放在一个报文中。

2. 问题：HTTP 的非持续连接和持续连接有什么区别？各自的优缺点是什么？

   答案：区别：非持续连接中每个 TCP 连接只传输一个请求报文和一个响应报文，下载多个对象需要多次 TCP 连接；持续连接中所有客户端和服务器的请求 / 响应对都经相同的 TCP 连接发送，下载多个对象仅需要一次 TCP 连接。

   非持续连接（HTTP1.0）优缺点：

   - 优点：实现简单；
   - 缺点：时间开销大（请求每个对象需要 2 个 RTT）；资源开销大（浏览器通常打开多个 TCP 连接）。

   持续连接（HTTP1.1）优缺点：

   - 优点：降低时间开销（无需多次建立 TCP 连接）和资源开销（减少 TCP 连接数量）；
   - 缺点：实现相对复杂，服务器需维护连接状态。

3. 问题：HTTP 请求报文和响应报文的结构分别是什么？

   答案：HTTP 请求报文结构：

   - 请求行：方法（Get/Post/Head/Put/Delete 等）+ 空格 + URL + 空格 + HTTP 版本 + 回车换行符；
   - 首部行：首部字段名 + 冒号 + 空格 + 值 + 回车换行符（可多个）；
   - 报文体：Post 方法使用，用于提交表单（首部行结束后加回车换行符标识报文体开始）。

   HTTP 响应报文结构：

   - 状态行：HTTP 版本 + 空格 + 状态码 + 空格 + 状态信息 + 回车换行符；
   - 首部行：首部字段名 + 冒号 + 空格 + 值 + 回车换行符（可多个）；
   - 报文体（实体体）：请求的对象数据（首部行结束后加回车换行符标识报文体开始）。

5. 问题：Cookie 技术的构成是什么？其作用和优缺点分别是什么？

   答案：Cookie 技术的构成：

   - HTTP 响应报文中的 cookie 首部行；
   - HTTP 请求报文中的 cookie 首部行；
   - 客户端保留的 cookie 文件（由浏览器进行管理）；
   - 服务器端在后端数据库产生的相应表项。

   Cookie 的作用：维护用户和服务器的状态，支持认证、购物、个性化推荐等功能。

   Cookie 的优点：

   - 能分析用户喜好，向用户进行个性化推荐；
   - 可标识用户信息，记录用户购物清单；
   - 可保存 4K 内容，跟踪用户浏览网站的喜好；
   - 可跨站点跟踪用户点击广告。

   Cookie 的缺点：

   - 能跟踪用户网络浏览痕迹，泄露用户隐私（如浏览过的网站、关注的关键词等）；
   - 存在被误解为嵌入间谍程序的误区（实际 Cookie 文件仅保存文本串，无执行程序）。

6. 问题：Web 缓存的作用是什么？条件 Get 方法的原理是什么？

   答案：Web 缓存的作用：

   - 大大减少响应时间：若请求对象在缓存中，可直接返回，无需访问源服务器；
   - 大大减少接入网到 Internet 的通信量，降低资费；
   - 大大减少 Internet 上的 Web 流量，改善网络性能。

   条件 Get 方法的原理：目的是确保 Web 缓存中保存的对象是最新版本；缓存服务器发出的 Get 请求报文中含有 “If Modified-Since:\<date\>” 的首部行；若对象在该日期之后没有被修改，源服务器返回 304 Not Modified 响应（无报文体），缓存服务器直接使用缓存中的对象；若对象在该日期之后被修改，源服务器返回 200 OK 响应，附带修改后的对象数据，缓存服务器更新缓存并返回给客户端。

### （四）E-mail 相关

1. 问题：E-mail 系统的组成部分有哪些？各部分的作用是什么？

   答案：E-mail 系统由用户代理、邮件服务器、SMTP 协议、邮件访问协议（POP3/IMAP/HTTP）组成。

   - 用户代理：即邮件客户端软件，供用户编写、发送、接收和阅读邮件；
   - 邮件服务器：包含输出报文队列（存储发送方待发送的邮件）和邮箱（存储接收方收到的邮件），是邮件传输的中转节点；
   - SMTP 协议：用于发送电子邮件，客户端为用户代理 / 发送邮件服务器，服务器为接收邮件服务器，实现发送邮件服务器到接收邮件服务器的直接传输；
   - 邮件访问协议（POP3/IMAP）：供邮件客户端从服务器获取邮件信息，其中 POP3 支持认证、下载、标记删除和更新功能，IMAP 支持远程管理邮件（创建文件夹、移动邮件等）

2. 问题：POP3、IMAP、HTTP 三种邮件访问协议的区别是什么？各自的特点是什么？

   答案：

   - POP3（Post Office Protocol v3）：

     - 端口：使用 TCP，端口 110；

     - 工作阶段：分为认证、事务处理（下载、标记删除）、更新（删除）三个阶段；

     - 邮件存储：邮件下载到客户端后，服务器端可默认删除，主要依赖客户端本地管理邮件；

     - 核心特点：功能简洁，仅支持基本的邮件下载和删除操作，适用于对邮件管理需求简单的场景。

   - IMAP（Internet Mail Access Protocol）：
     - 端口：使用 TCP，端口 143；
     - 邮件存储：邮件始终保留在服务器端，客户端通过远程操作管理邮件；
     - 核心特点：支持远程创建文件夹、远程移动邮件、远程查询邮件、获取邮件部分信息等功能，灵活性和功能性更强，适用于需要多设备同步邮件、精细化管理邮件的场景。
   - HTTP（基于 Web 的邮件访问协议）：
     - 核心特点：用户代理为浏览器，提供位于 POP3/IMAP 之上的、基于 Web 的邮件信息获取访问接口；无需安装专门的邮件客户端，通过浏览器即可访问邮件服务器，操作便捷，适用于临时访问或对客户端安装有限制的场景。
