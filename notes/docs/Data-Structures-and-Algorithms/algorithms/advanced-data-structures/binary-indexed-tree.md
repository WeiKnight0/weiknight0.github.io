# Binary Indexed Tree 树状数组

树状数组（Binary Indexed Tree, Fenwick Tree）解决的是这样一类问题：数组会被修改，同时又要频繁查询前缀和或区间和。最常见的操作是：

- 单点修改：把 `a[i]` 增加 `delta`
- 前缀查询：求 `a[1] + a[2] + ... + a[i]`
- 区间查询：求 `a[l] + ... + a[r]`

如果只用普通前缀和，查询很快，但修改 `a[i]` 后，后面所有前缀和都要更新。如果只用原数组，修改很快，但每次查询区间和都要重新累加。树状数组折中处理：它不存完整前缀和，而是存一组可以拼出前缀和的短区间和。

## lowbit 是什么

`lowbit(i)` 表示整数 `i` 的二进制表示中，最低位的 `1` 所代表的数值。等价地说，它是能整除 `i` 的最大 2 的幂。

代码写法：

```cpp
int lowbit(int i) {
    return i & -i;
}
```

例如：

| 十进制 i | 二进制 | lowbit(i) | 含义 |
| :--- | :--- | :--- | :--- |
| 1 | `0001` | 1 | 最低位的 `1` 是 `1` |
| 2 | `0010` | 2 | 最低位的 `1` 是 `2` |
| 3 | `0011` | 1 | 最低位的 `1` 是 `1` |
| 4 | `0100` | 4 | 最低位的 `1` 是 `4` |
| 6 | `0110` | 2 | 最低位的 `1` 是 `2` |
| 8 | `1000` | 8 | 最低位的 `1` 是 `8` |

为什么 `i & -i` 能得到 `lowbit(i)`？

在补码表示下，`-i` 等于 `~i + 1`。取反再加一之后，`i` 最低位的那个 `1` 会被保留下来，而它左边的位会与原数相反。再和原数做按位与，最终只剩这个最低位的 `1`。

例如 `i = 6`：

```text
 i =  0110
-i =  1010
&  =  0010
```

所以 `lowbit(6) = 2`。

在树状数组里，`lowbit(i)` 不只是一个位运算技巧。它直接决定 `tree[i]` 管辖的区间长度。

## tree 数组存的是什么

设原数组为 `a[1...n]`，树状数组为 `tree[1...n]`。树状数组的设计目标是：把一个前缀 `[1, i]` 拆成若干个不重叠的小区间，每个小区间的和已经缓存在某个 `tree[x]` 中。

每个 `tree[i]` 管辖一个以 `i` 为右端点的区间，区间长度正好是 `lowbit(i)`。严格定义：

```text
tree[i] = a[i - lowbit(i) + 1] + ... + a[i]
```

也就是：

\[
tree[i] = \sum_{k = i - lowbit(i) + 1}^{i} a[k]
\]

所以 `tree[i]` 不是 `a[i]`，也不是 `a[1] + ... + a[i]`。它只负责一段后缀式的小区间：右端点固定为 `i`，左端点由 `lowbit(i)` 决定。

以 `n = 8` 为例：

| 下标 i | lowbit(i) | 起始下标 | `tree[i]` 的内容 |
| :--- | :--- | :--- | :--- |
| 1 | 1 | 1 | `a[1]` |
| 2 | 2 | 1 | `a[1] + a[2]` |
| 3 | 1 | 3 | `a[3]` |
| 4 | 4 | 1 | `a[1] + a[2] + a[3] + a[4]` |
| 5 | 1 | 5 | `a[5]` |
| 6 | 2 | 5 | `a[5] + a[6]` |
| 7 | 1 | 7 | `a[7]` |
| 8 | 8 | 1 | `a[1] + ... + a[8]` |

结论：`tree` 是一个区间和缓存数组。不同下标缓存的区间长短不一样，但长度一定是 2 的幂，具体长度由 `lowbit(i)` 决定。

## 为什么叫树状数组

树状数组之所以叫“树状”，不是因为代码里显式建了一棵树，而是因为下标之间天然有父子关系。定义：

```text
parent(i) = i + lowbit(i)
```

如果 `parent(i) <= n`，就可以从 `i` 向 `parent(i)` 连一条边。这个父节点管辖的区间更大，并且会包含子节点管辖的区间。

以 `n = 8` 为例：

| 子节点 i | lowbit(i) | 父节点 `i + lowbit(i)` |
| :--- | :--- | :--- |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 1 | 4 |
| 4 | 4 | 8 |
| 5 | 1 | 6 |
| 6 | 2 | 8 |
| 7 | 1 | 8 |
| 8 | 8 | 超出边界 |

对应的拓扑结构是：

```text
         [8]
        / | \
       /  |  \
     [4] [6] [7]
     / \   |
   [2] [3] [5]
   |
  [1]
```

这个结构不是额外存出来的树，而是下标通过 `i + lowbit(i)` 自然形成的父子关系。数组 `tree` 存的是区间和，下标关系构成了树状拓扑，所以叫树状数组。

## 单点修改为什么向上走

假设执行：

```cpp
add(3, 5);
```

含义是把 `a[3]` 增加 `5`。由于 `tree` 里缓存的是若干区间和，所有包含位置 `3` 的缓存区间都必须同步增加 `5`。

在 `n = 8` 中：

- `tree[3]` 覆盖 `[3, 3]`
- `tree[4]` 覆盖 `[1, 4]`
- `tree[8]` 覆盖 `[1, 8]`

这些需要更新的下标，正好是沿父指针走出来的路径：

```text
3 -> 4 -> 8
```

代码就是：

```cpp
void add(int i, int delta) {
    for (; i <= n; i += lowbit(i)) {
        tree[i] += delta;
    }
}
```

这里的 `i += lowbit(i)` 就是从当前节点走到父节点。也就是说，单点修改不是随便跳，而是在更新所有包含当前位置的更大缓存区间。

## 前缀查询为什么向左跳

查询 `pre(i)` 表示求：

```text
a[1] + a[2] + ... + a[i]
```

它使用的方向是：

```text
i -= lowbit(i)
```

查询前缀和时，目标是拼出完整区间 `[1, i]`。每次取当前右端点能覆盖的最大一段区间，然后跳到这段区间的左边，继续取下一段。

以 `pre(7)` 为例：

- 先取 `tree[7]`，覆盖 `[7, 7]`
- 再跳到 `7 - lowbit(7) = 6`，取 `tree[6]`，覆盖 `[5, 6]`
- 再跳到 `6 - lowbit(6) = 4`，取 `tree[4]`，覆盖 `[1, 4]`
- 再跳到 `0`，停止

这三段互不重叠，拼起来正好是：

```text
[1, 4] + [5, 6] + [7, 7] = [1, 7]
```

对应代码：

```cpp
int pre(int i) {
    int res = 0;
    for (; i > 0; i -= lowbit(i)) {
        res += tree[i];
    }
    return res;
}
```

也可以写成：

```cpp
int pre(int i) {
    int res = 0;
    for (; i > 0; i &= i - 1) {
        res += tree[i];
    }
    return res;
}
```

因为 `i &= i - 1` 的作用是删掉 `i` 二进制最低位的 `1`，效果等价于 `i -= lowbit(i)`。查询方向和更新方向不同：更新是找更大的包含区间，查询是把前缀拆成若干已经缓存好的区间。

## 区间查询

树状数组直接支持前缀和。普通区间和可以通过两个前缀和相减得到：

```cpp
int query(int l, int r) {
    return pre(r) - pre(l - 1);
}
```

数学上就是：

```text
a[l] + ... + a[r]
= (a[1] + ... + a[r]) - (a[1] + ... + a[l - 1])
```

## 完整基础实现

树状数组通常使用 `1-indexed` 下标。

```cpp
class Fenwick {
    int n;
    vector<int> tree;

    int lowbit(int i) {
        return i & -i;
    }

public:
    Fenwick(int n) : n(n), tree(n + 1) {}

    void add(int i, int delta) {
        for (; i <= n; i += lowbit(i)) {
            tree[i] += delta;
        }
    }

    int pre(int i) {
        int res = 0;
        for (; i > 0; i -= lowbit(i)) {
            res += tree[i];
        }
        return res;
    }

    int query(int l, int r) {
        return pre(r) - pre(l - 1);
    }
};
```

如果原数组是 `0-indexed`，常见做法是在调用树状数组时整体加一：

```cpp
// 修改 a[idx]，idx 是 0-indexed
fenwick.add(idx + 1, delta);

// 查询 a[l] + ... + a[r]，l 和 r 是 0-indexed
fenwick.query(l + 1, r + 1);
```

不要直接从 `0` 开始做树状数组循环，因为 `lowbit(0) = 0`，`add` 中的 `i += lowbit(i)` 会无法推进。

## 复杂度

- 单点修改：`O(log n)`
- 前缀查询：`O(log n)`
- 区间查询：`O(log n)`
- 空间复杂度：`O(n)`

树状数组适合处理“单点修改 + 前缀/区间查询”的问题。它的关键点只有两个：`tree[i]` 管辖长度为 `lowbit(i)` 的区间，修改时用 `i += lowbit(i)` 找所有包含当前位置的缓存区间，查询时用 `i -= lowbit(i)` 把前缀拆成若干缓存区间。

如果需要区间修改、区间查询，也可以通过差分或维护多个树状数组扩展，但基础结构仍然来自这里的 `lowbit` 分段方式。
