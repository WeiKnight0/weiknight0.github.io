# B-Tree and B+ Tree B 树与 B+ 树

普通二叉查找树在大规模外存数据中层数较多，每下降一层都可能引发一次磁盘或页面 I/O。B 树和 B+ 树让一个节点容纳多个关键字和多棵子树，通过提高分支数显著降低树高。

## B 树

B 树是面向外存的多路平衡查找树。一棵 $m$ 阶 B 树满足：

- 每个节点至多有 $m$ 棵子树和 $m-1$ 个关键字。
- 除根节点外，非叶节点至少有 $\lceil m/2\rceil$ 棵子树。
- 非叶根节点至少有两棵子树。
- 一个节点有 $k$ 棵子树时恰有 $k-1$ 个关键字。
- 每个节点内的关键字递增排列，并将各子树的关键字范围分开。
- 所有叶节点都在同一层。

### 查找

先在当前节点内查找关键字。命中时查找成功；未命中时，根据关键字所在区间进入对应子树。节点内查找在内存中完成，树的高度决定外存 I/O 次数。

### 插入

新关键字总是插入最底层的非叶节点。若插入后关键字数超过 $m-1$，则以中间关键字为界将节点分裂为左右两部分，并将中间关键字提升到父节点。分裂可能一直向根传播；根节点分裂时树高增加 $1$。

### 删除

删除非最底层关键字时，先用其前驱或后继替换，再转化为删除最底层关键字。若删除后节点关键字过少：

1. 相邻兄弟关键字足够时，通过父节点向兄弟借一个关键字。
2. 兄弟也达到最少关键字数时，将父节点中的分隔关键字下移，与两个节点合并。

合并可能一直向根传播；根节点在合并后不再包含关键字时，其唯一子节点成为新根，树高减少 $1$。

## B+ 树

B+ 树常用于数据库和文件系统索引。一棵 $m$ 阶 B+ 树中：

- 每个分支节点至多有 $m$ 棵子树。
- 非叶根节点至少有两棵子树，其他分支节点至少有 $\lceil m/2\rceil$ 棵子树。
- 一个节点有 $k$ 棵子树时对应 $k$ 个关键字。
- 分支节点中的关键字是子树最大或最小关键字的副本，只用于索引。
- 所有数据记录都保存在叶节点。
- 叶节点按关键字有序链接。

B+ 树支持两种查找方式：从根开始的多路查找，以及从最小叶节点开始沿链表的顺序查找。任何成功的随机查找都会到达叶节点。

## B 树与 B+ 树的对比

| 特性 | B 树 | B+ 树 |
| --- | --- | --- |
| 数据记录 | 分支节点和最底层节点都可以保存 | 只保存在叶节点 |
| 分支节点关键字 | 只出现一次 | 是叶节点关键字的副本 |
| 成功查找 | 可能在任意层结束 | 总是到达叶节点 |
| 范围查询 | 需要跨层遍历 | 可以沿叶节点链表顺序访问 |
| 节点扇出 | 较小 | 分支节点不存记录，通常能容纳更多索引 |
